# dtk-rs — agent guide

Rust bindings for DTK6 (dtkwidget): write deepin apps with DTK UIs in pure Rust.

## Layout

```
dtk-sys/     FFI layer, unsafe. links = "dtk6widget"
  cpp/       C++ shim: shim.cpp (hand), dtk_gen_shim.cpp (generated), relay.cpp (signal relay)
  include/   headers, relay.h has Q_OBJECT (needs moc)
  src/lib.rs      cxx::bridge #1, hand-written core
  src/gen_ffi.rs  cxx::bridge #2, GENERATED by tools/gen.py
  build.rs        pkg-config Qt6/DTK6, runs moc, c++17 + -fPIC
dtk/         safe wrappers
  src/lib.rs      hand-written core classes
  src/widgets.rs  GENERATED by tools/gen.py (~60 DTK classes)
tools/gen.py header-scanning generator; parses /usr/include/dtk6/DWidget/*.h
GEN_REPORT.md generator coverage report (skipped methods + reasons)
TODO.md      known gaps
```

**Generated files** (regenerate, don't hand-edit): `dtk/src/widgets.rs`, `dtk-sys/src/gen_ffi.rs`, `dtk-sys/cpp/dtk_gen_shim.cpp`, `dtk-sys/include/dtk_gen_shim.h`.

## Commands

```sh
cargo build                                    # build all
cargo run --example demo                       # GUI demo
QT_QPA_PLATFORM=offscreen ./target/debug/examples/demo --smoke   # headless smoke test
python3 tools/gen.py && cargo build            # regenerate bindings
```

No test suite; the demo `--smoke` mode + `examples/dialog_selfcheck.rs` are the checks.

## Hard rules

- Requires Linux with Qt6 + DTK6 dev packages (pkg-config must find `Qt6Widgets`, `dtk6widget`, etc.). Not cross-platform.
- Rust edition 2024. `unsafe` blocks need `unsafe extern` etc. — edition 2024 lint strictness applies.
- Rust wrappers are **non-owning raw pointers**: `!Send`, single GUI thread, Qt parent-child owns lifetimes.
- Value-type wrappers (QColor, QFont, ...) free via shim `*_delete` in `Drop` — never leak intentionally.
- Two cxx bridges; only `QWidget*` (and listed types) cross between them via `as _` cast — sound per audit, see comments in tools/gen.py.
- New DTK method → usually regenerate with gen.py, not handwritten. If param types unmapped (QList, QVariant, QAction*, ...), it lands in GEN_REPORT.md skipped — that's expected, see TODO.md for plan.
- Signals: use `connect_signal*` / typed helpers; unregister via `dtk::unregister_callback(id)` when done.
- `.codegraph/`, `target/`, `tools/__pycache__/` are gitignored scratch — don't commit.

## Style

- Minimal diffs. Hand-written code lives in `dtk/src/lib.rs` / `dtk-sys/src/lib.rs` + `cpp/shim.cpp`; keep generator-owned files generator-owned.
- Type mapping conventions (QString↔&str, enums→i32 with `dtk::qt` constants) are documented in README.md "Design" — follow them.
